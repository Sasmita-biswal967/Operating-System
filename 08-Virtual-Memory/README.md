
# Unit 8: Virtual Memory

## 1. Introduction to Virtual Memory

Virtual Memory is a memory management technique that allows a process to execute even when the entire process is not loaded into physical memory (RAM).

It provides an abstraction of a large memory space to processes.

Only the required portions of a process are loaded into RAM. The remaining portions stay in secondary storage until needed.

### Why is Virtual Memory Required?

Suppose:

```text
Physical RAM = 4 GB
Process Size = 8 GB
```

Normally, the entire process cannot fit into RAM.

Using virtual memory, the operating system can load only the required pages into RAM and keep the remaining pages on secondary storage.

### Advantages

- Allows programs larger than physical memory to execute.
- Improves memory utilization.
- Supports more concurrent processes.
- Provides process isolation.
- Avoids loading unused portions of programs into RAM.

### Disadvantages

- Page faults introduce overhead.
- Accessing secondary storage is much slower than RAM.
- Excessive page faults can cause thrashing.
- Requires additional hardware and operating system support.

---

## 2. Virtual Address Space vs Physical Address Space

### Virtual Address Space

The range of addresses that a process can use.

It is also called the logical address space.

### Physical Address Space

The actual range of addresses available in physical memory.

### Difference

| Virtual Address Space | Physical Address Space |
|---|---|
| Used by a process | Represents actual RAM locations |
| Generated by CPU | Used to access physical memory |
| Can be larger than RAM | Limited by available physical memory |
| Translated by MMU | Final address after translation |

### Example

```text
Virtual Address Space = 8 GB
Physical RAM = 4 GB
```

A process can have an 8 GB virtual address space even though only a portion of its pages are resident in RAM at a given time.

**Important:** Virtual address space is not the same as the amount of RAM allocated to a process.

---

## 3. How Virtual Memory Works

Virtual memory uses address translation to map virtual pages to physical frames.

The page table stores the mapping.

```text
        CPU
         |
         v
  Virtual Address
         |
         v
        MMU
         |
         v
     Page Table
         |
     +---+---+
     |       |
   Valid   Invalid/
   Mapping Not Present
     |       |
     v       v
 Physical  Page Fault
 Memory       |
              v
       Operating System
              |
              v
       Load Required Page
              |
              v
       Update Page Table
              |
              v
        Resume Process
```

### Working

1. CPU generates a virtual address.
2. MMU checks the page table or translation cache.
3. If the required page is present in RAM, the address is translated.
4. If the page is not present, a page fault occurs.
5. The operating system locates the required page in secondary storage.
6. It loads the page into a free frame or replaces another page.
7. The page table is updated.
8. The interrupted instruction is restarted.

---

## 4. Demand Paging

Demand Paging is a virtual memory technique in which a page is loaded into RAM only when it is required.

Instead of loading all pages of a process at once, the operating system loads pages on demand.

### Example

Suppose a process contains 10 pages:

```text
P0 P1 P2 P3 P4 P5 P6 P7 P8 P9
```

Initially, only these pages are required:

```text
P0 P2 P5
```

Only these pages need to be loaded into RAM.

When the process accesses P7, the operating system loads P7.

### Advantages

- Reduces initial loading time.
- Saves physical memory.
- Allows more processes to remain active.
- Avoids loading unused pages.

### Disadvantages

- Page faults cause overhead.
- Requires page replacement when no free frame is available.
- Performance can degrade if page faults occur frequently.

---

## 5. Page Fault

A page fault occurs when a process accesses a virtual page that is not currently mapped to a usable physical memory frame.

The operating system must handle the fault.

### Steps Involved in Page Fault Handling

1. CPU generates a virtual address.
2. MMU detects that the required page is not present or the access is invalid.
3. A page-fault exception is generated.
4. The operating system checks whether the memory access is legal.
5. If the access is invalid, the process may be terminated or an exception may be delivered.
6. If the access is valid, the OS locates the page on secondary storage.
7. It finds a free frame or selects a victim page.
8. If the victim page is dirty, it is written back to storage.
9. The required page is loaded into RAM.
10. Page table and TLB entries are updated as necessary.
11. The interrupted instruction is restarted.

### Page Fault Flowchart

```text
       Page Access
            |
            v
      Page Present?
        /       \
      Yes        No
       |          |
       v          v
   Access Data  Page Fault
                    |
                    v
              Valid Access?
                /      \
              Yes       No
               |         |
               v         v
         Find Free      Invalid
           Frame        Access
               |         |
               v         v
         Load Page    Raise Exception
               |
               v
         Update Page Table
               |
               v
         Restart Instruction
```

### Important Point

Not every page fault indicates an error.

A valid page may simply not be present in RAM yet.

---

## 6. Valid-Invalid Bit

Each page table entry can contain a valid-invalid or present-absent status bit.

It helps the operating system determine whether a page is currently available in physical memory.

### Example

| Page | Status |
|---|---|
| P0 | Valid |
| P1 | Invalid |
| P2 | Valid |
| P3 | Invalid |

If the process accesses P1, the system may generate a page fault because the page is not currently resident.

**Note:** Different architectures distinguish present bits, validity bits, and protection bits in different ways. An invalid mapping may indicate an illegal address rather than a page that can simply be loaded.

---

## 7. Page Replacement

Page replacement is required when a page fault occurs and no free physical frame is available.

The operating system selects an existing page to remove from RAM and loads the required page into its frame.

The removed page is called the victim page.

### Why is Page Replacement Needed?

Suppose:

```text
Number of Frames = 3
```

RAM currently contains:

```text
P1, P2, P3
```

A process requests P4.

Since all frames are occupied, one existing page must be replaced.

### Page Replacement Algorithms

Important algorithms:

1. FIFO
2. Optimal
3. LRU
4. Second Chance / Clock

---

## 8. FIFO Page Replacement Algorithm

FIFO stands for First In First Out.

The page that entered memory earliest is removed first.

It works like a queue.

### Working

- Maintain pages in a queue.
- Insert new pages at the rear.
- Remove the oldest page from the front when replacement is required.

### Example

Reference String:

```text
1, 2, 3, 4, 1, 2, 5
```

Number of Frames:

```text
3
```

| Reference | Frame 1 | Frame 2 | Frame 3 | Result |
|---|---|---|---|---|
| 1 | 1 | - | - | Fault |
| 2 | 1 | 2 | - | Fault |
| 3 | 1 | 2 | 3 | Fault |
| 4 | 4 | 2 | 3 | Fault |
| 1 | 4 | 1 | 3 | Fault |
| 2 | 4 | 1 | 2 | Fault |
| 5 | 5 | 1 | 2 | Fault |

Total Page Faults:

```text
7
```

### Advantages

- Simple to implement.
- Easy to understand.
- Uses a queue.

### Disadvantages

- May remove frequently used pages.
- Does not consider how recently a page was used.
- Can suffer from Belady's Anomaly.

---

## 9. Optimal Page Replacement Algorithm

Optimal Page Replacement replaces the page whose next use is farthest in the future.

If a page will never be used again, it is an ideal candidate for replacement.

### Working

1. When a page fault occurs, inspect future references.
2. Identify the page whose next use is farthest away.
3. Replace that page.

### Example

Reference String:

```text
1, 2, 3, 4, 1, 2, 5
```

Number of Frames:

```text
3
```

| Reference | Frame 1 | Frame 2 | Frame 3 | Result |
|---|---|---|---|---|
| 1 | 1 | - | - | Fault |
| 2 | 1 | 2 | - | Fault |
| 3 | 1 | 2 | 3 | Fault |
| 4 | 1 | 2 | 4 | Fault |
| 1 | 1 | 2 | 4 | Hit |
| 2 | 1 | 2 | 4 | Hit |
| 5 | 1 | 2 | 5 | Fault |

Total Page Faults:

```text
5
```

### Advantages

- Produces the minimum possible number of page faults for a given reference string and number of frames.
- Useful as a benchmark for other algorithms.

### Disadvantages

- Requires knowledge of future page references.
- Cannot be implemented exactly in a general-purpose operating system.

**Important:** Optimal Page Replacement is mainly used for comparison and theoretical analysis.

---

## 10. LRU Page Replacement Algorithm

LRU stands for Least Recently Used.

It replaces the page that has not been used for the longest period of time.

It uses past references rather than future references.

### Working

1. Track when each page was last accessed.
2. When a replacement is needed, identify the least recently used page.
3. Replace it with the requested page.

### Example

Reference String:

```text
1, 2, 3, 4, 1, 2, 5
```

Number of Frames:

```text
3
```

| Reference | Frame 1 | Frame 2 | Frame 3 | Result |
|---|---|---|---|---|
| 1 | 1 | - | - | Fault |
| 2 | 1 | 2 | - | Fault |
| 3 | 1 | 2 | 3 | Fault |
| 4 | 4 | 2 | 3 | Fault |
| 1 | 4 | 1 | 3 | Fault |
| 2 | 4 | 1 | 2 | Fault |
| 5 | 5 | 1 | 2 | Fault |

Total Page Faults:

```text
7
```

### Advantages

- Uses recent usage history.
- Usually performs better than FIFO on many workloads.
- Does not suffer from Belady's Anomaly.

### Disadvantages

- Requires tracking page usage.
- Exact implementations may require additional hardware or data structures.
- Can introduce overhead.

---

## 11. Comparison of Page Replacement Algorithms

| Algorithm | Replacement Strategy | Future Knowledge Required? | Belady's Anomaly |
|---|---|---|---|
| FIFO | Oldest loaded page | No | Possible |
| Optimal | Page used farthest in future | Yes | No |
| LRU | Least recently used page | No | No |
| Second Chance | FIFO with reference-bit check | No | Possible |

For the example reference string:

```text
1, 2, 3, 4, 1, 2, 5
```

With 3 frames:

| Algorithm | Page Faults |
|---|---:|
| FIFO | 7 |
| Optimal | 5 |
| LRU | 7 |

**Important:** These counts apply to this specific reference string and frame count. Different reference strings produce different results.

## 14. Belady's Anomaly

Belady's Anomaly is a situation in which increasing the number of page frames results in an increase in the number of page faults.

It can occur in FIFO page replacement.

### Example

Reference String:

```text
1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5
```

Using FIFO:

| Number of Frames | Page Faults |
|---|---:|
| 3 | 9 |
| 4 | 10 |

Although the number of frames increased from 3 to 4, the number of page faults also increased.

This is Belady's Anomaly.

### Important Points

- Commonly demonstrated using FIFO.
- Does not occur in LRU.
- Does not occur in Optimal.
- Stack algorithms do not suffer from Belady's Anomaly.

---

## 15. Stack Algorithms

A stack algorithm is a page replacement algorithm in which the set of pages in memory with n frames is always a subset of the pages in memory with n+1 frames, for the same reference history.

### Examples

- LRU
- Optimal

These algorithms do not suffer from Belady's Anomaly.

FIFO is not a stack algorithm.

---

## 16. Second Chance Page Replacement Algorithm

Second Chance is an improvement over FIFO.

It uses a reference bit to decide whether a page should be replaced.

### Reference Bit

Each page has a reference bit:

```text
R = 0 -> Page has not been referenced recently
R = 1 -> Page has been referenced recently
```

### Working

1. Check the oldest page.
2. If its reference bit is 0, replace it.
3. If its reference bit is 1:
   - Set the reference bit to 0.
   - Give the page a second chance.
   - Move to the next page.
4. Continue until a page with reference bit 0 is found.

### Clock Algorithm

The Clock algorithm is an efficient implementation of Second Chance.

Pages are arranged in a circular structure.

A pointer moves around the pages to find a replacement candidate.

### Advantages

- Better than simple FIFO in many situations.
- Uses a reference bit.
- Does not require exact tracking of access times.

---

## 17. Page Fault Frequency

Page Fault Frequency (PFF) is a technique that monitors how frequently page faults occur.

The operating system can adjust the number of frames allocated to a process based on its page fault frequency.

### Working

- If page fault frequency is too high, allocate more frames if possible.
- If page fault frequency is low, some frames may be taken away and allocated elsewhere.

### Purpose

- Controls memory allocation.
- Helps reduce thrashing.
- Improves system performance.

---

## 18. Thrashing

Thrashing occurs when a system spends more time handling page faults and swapping pages than executing actual processes.

It happens when processes do not have enough frames to hold their actively used pages.

### Example

Suppose a process frequently accesses:

```text
P1, P2, P3, P4
```

But it has only two frames.

Pages keep replacing one another.

The process generates frequent page faults and spends more time loading pages than executing instructions.

### Symptoms

- Very high page fault rate.
- Heavy paging activity.
- Low CPU utilization.
- Poor system performance.
- Increased disk activity.

### Causes

- Insufficient physical memory.
- Too many processes in memory.
- Too few frames allocated to processes.
- Poor locality of reference.
- Excessive degree of multiprogramming.

### How to Prevent Thrashing?

- Reduce the degree of multiprogramming.
- Allocate more frames to affected processes.
- Use the Working Set Model.
- Use Page Fault Frequency control.
- Add more physical memory where appropriate.

---

## 19. Locality of Reference

Locality of Reference is the tendency of a process to access a relatively small portion of its address space repeatedly during a period of time.

It is important in virtual memory because recently accessed pages are often likely to be accessed again.

### Types of Locality

#### 1. Temporal Locality

If a memory location is accessed, it is likely to be accessed again soon.

Example:

A loop repeatedly accesses the same variable.

```c
for (int i = 0; i < 100; i++) {
    sum += 10;
}
```

#### 2. Spatial Locality

If a memory location is accessed, nearby memory locations are likely to be accessed soon.

Example:

Accessing consecutive array elements.

```c
for (int i = 0; i < 100; i++) {
    arr[i] = i;
}
```

#### 3. Sequential Locality

Instructions are often executed in sequence.

Example:

Normal execution of consecutive instructions in a program.

### Importance

Locality of reference helps explain why:
- Cache memory is effective.
- Paging works efficiently.
- LRU often performs well.
- Working Set models are useful.

---

## 20. Working Set Model

The Working Set Model is a technique used to control thrashing.

The working set of a process is the set of pages referenced during a recent window of execution.

Let:

```text
WSS = Working Set Size
```

It represents the number of distinct pages in the working set.

Let:

```text
D = Total demand for frames
m = Total available frames
```

Then:

```text
D = Sum of WSS for all processes
```

### Condition

If:

```text
D <= m
```

The system can potentially allocate enough frames to satisfy the working sets.

If:

```text
D > m
```

The system may experience thrashing.

The operating system may reduce the degree of multiprogramming by suspending one or more processes.

### Example

Suppose:

```text
WSS(P1) = 4
WSS(P2) = 5
WSS(P3) = 3

Total Available Frames = 15
```

Total demand:

```text
D = 4 + 5 + 3
  = 12
```

Since:

```text
12 <= 15
```

The system has enough frames to satisfy the estimated working sets.

Now suppose only 10 frames are available.

```text
12 > 10
```

The system may experience thrashing.

## 21. Global vs Local Page Replacement

### Global Page Replacement

A process can replace a page belonging to another process.

The replacement algorithm selects a victim from the system's available pool of resident pages.

Advantages:
- Flexible frame allocation.
- Can improve overall memory utilization.

Disadvantages:
- One process can affect another process's performance.
- Frame allocation may become unpredictable.

### Local Page Replacement

A process can replace only pages from its own allocated frames.

Advantages:
- Better process isolation.
- One process is less likely to affect another's page replacement behavior.

Disadvantages:
- A process may suffer high page fault rates even when another process has unused frames.

### Comparison

| Global Replacement | Local Replacement |
|---|---|
| Can replace pages from other processes | Replaces only its own pages |
| System-wide frame pool | Process-specific frame allocation |
| More flexible | More isolated |
| Can cause interference | Limits interference |

---

## 22. Page Replacement vs Frame Allocation

### Page Replacement

Decides which page should be removed when a new page must be loaded and no free frame is available.

### Frame Allocation

Decides how many physical frames should be allocated to each process.

### Frame Allocation Strategies

1. Equal Allocation
2. Proportional Allocation
3. Priority Allocation

#### Equal Allocation

Every process receives the same number of frames.

Example:

```text
Total Frames = 20
Processes = 4

Frames per Process = 20 / 4 = 5
```

#### Proportional Allocation

Frames are allocated according to process size.

Example:

```text
P1 Size = 100 KB
P2 Size = 200 KB

Total Frames = 30
```

Total process size:

```text
100 + 200 = 300 KB
```

P1 allocation:

```text
(100 / 300) * 30 = 10 frames
```

P2 allocation:

```text
(200 / 300) * 30 = 20 frames
```

#### Priority Allocation

Processes with higher priority may receive more frames than lower-priority processes.

## 23. Copy-on-Write (COW)

Copy-on-Write is a memory optimization technique in which two processes initially share the same physical memory pages.

A separate copy is created only when one process attempts to modify a shared page.

### Example

Suppose a parent process creates a child process.

Initially:

```text
Parent ----+
           |
           v
       Shared Page
           ^
           |
Child -----+
```

When the child modifies the shared page:

```text
Parent ------> Original Page

Child -------> New Copied Page
```

### Advantages

- Reduces unnecessary memory copying.
- Improves process creation efficiency.
- Saves physical memory.

### Common Use

Copy-on-Write is commonly used when implementing process creation with `fork()` in Unix-like operating systems.

---

## 24. Memory-Mapped Files

Memory-mapped files allow a file to be mapped into a process's virtual address space.

The process can access file contents using ordinary memory operations.

The operating system handles loading and writing pages as required.

### Advantages

- Convenient file access.
- Can reduce explicit read/write operations.
- Allows supported forms of shared memory between processes.
- Uses virtual memory mechanisms.

### Example

A process maps a file into memory and reads its contents using pointers rather than repeatedly calling file-read operations.

## 25. Important Formulas

### 1. Page Fault Rate

```text
Page Fault Rate = Number of Page Faults / Total Memory References
```

### 2. Page Hit Rate

```text
Page Hit Rate = Number of Page Hits / Total Memory References
```

### 3. Relationship

```text
Page Fault Rate + Page Hit Rate = 1
```

### 4. Working Set Demand

```text
D = Sum of Working Set Sizes of All Processes
```

### 5. Thrashing Risk

```text
D > Total Available Frames
```

### 6. Effective Access Time with Page Faults

A simplified model:

```text
EAT = (1 - p) * ma + p * pf
```

Where:

- p = Page fault probability.
- ma = Normal memory access time.
- pf = Average page fault service time.

This model assumes that the page-fault service time includes the additional work needed to handle the fault and restart the instruction.

### 7. Effective Access Time with TLB

For a single-level page table:

```text
EAT = h * (t + m) + (1 - h) * (t + 2m)
```

Where:

- h = TLB hit ratio.
- t = TLB lookup time.
- m = Main memory access time.

## 26. Important Interview Questions and Answers

### Q1. What is virtual memory?

Virtual memory is a memory management technique that allows processes to execute without loading their entire address space into physical memory.

### Q2. What is demand paging?

Demand paging loads a page into RAM only when it is accessed.

### Q3. What is a page fault?

A page fault occurs when a process accesses a virtual page that is not currently mapped to a usable physical memory frame.

### Q4. What happens when a page fault occurs?

The operating system validates the access, locates the page, loads it into RAM, updates the mapping, and restarts the interrupted instruction.

### Q5. What is page replacement?

Page replacement selects a page to remove from RAM when a new page must be loaded and no free frame is available.

### Q6. What is FIFO page replacement?

FIFO replaces the page that entered memory earliest.

### Q7. What is LRU page replacement?

LRU replaces the page that has not been used for the longest period.

### Q8. What is Optimal Page Replacement?

Optimal replaces the page whose next use is farthest in the future.

### Q9. Why is Optimal Page Replacement not used practically?

It requires knowledge of future memory references, which is generally unavailable during normal execution.

### Q10. What is Belady's Anomaly?

Belady's Anomaly occurs when increasing the number of page frames increases the number of page faults.

### Q11. Which algorithm suffers from Belady's Anomaly?

FIFO can suffer from Belady's Anomaly.

### Q12. Does LRU suffer from Belady's Anomaly?

No. LRU is a stack algorithm.

### Q13. What is thrashing?

Thrashing occurs when the system spends more time handling page faults and transferring pages than executing processes.

### Q14. What is locality of reference?

Locality of reference is the tendency of programs to access the same or nearby memory locations repeatedly.

### Q15. What is temporal locality?

Recently accessed memory locations are likely to be accessed again soon.

### Q16. What is spatial locality?

Memory locations near a recently accessed location are likely to be accessed soon.

### Q17. What is the Working Set Model?

It estimates the pages a process has recently used and helps determine the number of frames it needs.

### Q18. What is the difference between global and local page replacement?

Global replacement can select pages from other processes, while local replacement selects only from the current process's allocated frames.

### Q19. What is Copy-on-Write?

Copy-on-Write allows processes to share pages until one process attempts to modify a page, at which point a separate copy is created.

### Q20. What is the difference between a page fault and a TLB miss?

A TLB miss means the address translation is not cached. A page fault means the requested page is not currently available in physical memory or the access is invalid.

### Q21. What is the difference between FIFO and LRU?

FIFO replaces the oldest loaded page, while LRU replaces the least recently accessed page.

### Q22. What is the purpose of the Clock algorithm?

The Clock algorithm approximates LRU using reference bits and a circular pointer.

### Q23. What is page fault frequency?

It measures how frequently a process generates page faults and can be used to adjust its frame allocation.

### Q24. What is the difference between page replacement and frame allocation?

Page replacement chooses which page to remove, while frame allocation decides how many frames a process receives.

### Q25. What is a dirty page?

A dirty page is a page that has been modified since it was loaded into memory and may need to be written back before replacement.
