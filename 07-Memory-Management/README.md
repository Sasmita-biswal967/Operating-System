
# Unit 7: Memory Management

## 1. Introduction to Memory Management

Memory Management is an important function of an Operating System that manages the computer's main memory (RAM).

It is responsible for:
- Allocating memory to processes.
- Deallocating memory when processes finish.
- Keeping track of used and free memory.
- Protecting one process's memory from another.
- Translating logical addresses into physical addresses.
- Efficiently utilizing available memory.

### Why is Memory Management Required?

Suppose multiple processes are running simultaneously:

```text
P1 -> 100 MB
P2 -> 200 MB
P3 -> 150 MB
P4 -> 300 MB
```

The operating system must allocate memory to each process without allowing them to interfere with one another.

Memory management helps achieve efficient and safe memory utilization.

---

## 2. Basic Concepts of Memory Management

### 2.1 Main Memory

Main memory, also called RAM, stores programs and data that are currently being executed.

Characteristics:
- Directly accessible by the CPU.
- Volatile memory.
- Faster than secondary storage.
- Limited in capacity.

### 2.2 Memory Hierarchy

Memory is organized into different levels based on speed, cost, and capacity.

```text
          Registers
              |
              v
          Cache Memory
              |
              v
          Main Memory (RAM)
              |
              v
       Secondary Storage
        (SSD / HDD)
```

| Memory | Speed | Capacity |
|---|---|---|
| Registers | Fastest | Very small |
| Cache | Very fast | Small |
| RAM | Fast | Medium |
| SSD/HDD | Slower | Large |

### 2.3 Memory Management Unit (MMU)

The Memory Management Unit is a hardware component responsible for translating logical addresses into physical addresses.

It also supports memory protection and address translation mechanisms.

```text
       CPU
        |
        | Logical Address
        v
       MMU
        |
        | Physical Address
        v
    Main Memory
```

## 3. Logical Address vs Physical Address

### Logical Address

A logical address is the address generated by the CPU during program execution.

It is also called a virtual address in many contexts.

### Physical Address

A physical address is the actual address in main memory (RAM).

### Difference

| Logical Address | Physical Address |
|---|---|
| Generated by CPU | Actual address in RAM |
| Also called virtual address | Also called real address |
| Visible to the executing program | Used to access main memory |
| Translated by MMU | Final address after translation |

### Example

Suppose:

```text
Logical Address = 1000
Relocation Register = 5000
```

For simple relocation-based address translation:

```text
Physical Address = Logical Address + Relocation Register

                 = 1000 + 5000

                 = 6000
```

Therefore:

```text
Logical Address  = 1000
Physical Address = 6000
```

**Important:** This addition method applies to simple base/relocation-register systems. Paging and segmentation use different translation mechanisms.

## 4. Address Binding

Address binding refers to mapping program instructions and data to memory addresses.

It can happen at three stages.

### 4.1 Compile-Time Binding

If the memory location is known at compile time, absolute addresses can be generated.

If the starting location changes, the program must be recompiled.

### 4.2 Load-Time Binding

If the memory location is not known at compile time, relocatable addresses are generated.

The final addresses are determined when the program is loaded into memory.

### 4.3 Execution-Time Binding

Address binding occurs while the program is executing.

The process can be moved during execution because address translation is performed dynamically by hardware.

### Comparison

| Compile-Time | Load-Time | Execution-Time |
|---|---|---|
| Address fixed during compilation | Address determined during loading | Address translated during execution |
| Requires recompilation if location changes | Requires relocation when loaded | Supports dynamic relocation |
| Simple approach | More flexible than compile-time | Most flexible |

## 5. Contiguous Memory Allocation

In contiguous memory allocation, each process is allocated one continuous block of physical memory.

### Types

1. Fixed Partitioning
2. Variable Partitioning

### 5.1 Fixed Partitioning

Memory is divided into a fixed number of partitions.

Each partition can hold one process.

Example:

```text
+----------------------+
| Operating System     |
+----------------------+
| Partition 1: P1      |
+----------------------+
| Partition 2: P2      |
+----------------------+
| Partition 3: Free    |
+----------------------+
| Partition 4: P3      |
+----------------------+
```

Advantages:
- Simple to implement.
- Easy memory allocation.

Disadvantages:
- Causes internal fragmentation.
- Number of processes is limited by the number of partitions.
- Memory may be wasted inside partitions.

### 5.2 Variable Partitioning

Partitions are created dynamically according to process requirements.

Example:

```text
+----------------------+
| Operating System     |
+----------------------+
| P1: 100 MB           |
+----------------------+
| P2: 200 MB           |
+----------------------+
| Free Space: 150 MB   |
+----------------------+
| P3: 300 MB           |
+----------------------+
```

Advantages:
- More flexible allocation.
- Better utilization than fixed partitions in many situations.

Disadvantages:
- Causes external fragmentation.
- Allocation and deallocation are more complex.
- May require compaction.

## 6. Memory Allocation Algorithms

When a process requests memory, the operating system must decide which free memory block should be allocated.

Three common algorithms are:

1. First Fit
2. Best Fit
3. Worst Fit

### 6.1 First Fit

First Fit allocates the first available memory block that is large enough for the process.

Example:

Free blocks:

```text
100 KB, 500 KB, 200 KB, 300 KB, 600 KB
```

Process request:

```text
212 KB
```

The first block large enough is 500 KB.

Remaining space:

```text
500 - 212 = 288 KB
```

### 6.2 Best Fit

Best Fit allocates the smallest available block that is large enough for the process.

Example:

Free blocks:

```text
100 KB, 500 KB, 200 KB, 300 KB, 600 KB
```

Process request:

```text
212 KB
```

The smallest block that can accommodate the process is 300 KB.

Remaining space:

```text
300 - 212 = 88 KB
```

### 6.3 Worst Fit

Worst Fit allocates the largest available memory block.

Example:

Free blocks:

```text
100 KB, 500 KB, 200 KB, 300 KB, 600 KB
```

Process request:

```text
212 KB
```

The largest block is 600 KB.

Remaining space:

```text
600 - 212 = 388 KB
```

### Comparison

| Algorithm | Allocation Strategy |
|---|---|
| First Fit | First block large enough |
| Best Fit | Smallest block large enough |
| Worst Fit | Largest available block |

### Advantages and Disadvantages

| Algorithm | Advantage | Disadvantage |
|---|---|---|
| First Fit | Simple and usually fast | Can leave small holes near the beginning |
| Best Fit | Selects the closest-sized block | Can create many small unusable holes |
| Worst Fit | Leaves a relatively large remaining block | May waste large blocks |

**Interview Tip:** Best Fit does not always provide the best memory utilization. The result depends on the allocation sequence and available free blocks.

## 7. Fragmentation

Fragmentation occurs when memory is wasted because of the way memory is allocated and deallocated.

There are two main types:

1. Internal Fragmentation
2. External Fragmentation

### 7.1 Internal Fragmentation

Internal fragmentation occurs when allocated memory is larger than the memory actually required by a process.

The unused space inside the allocated block is wasted.

Example:

```text
Partition Size = 100 KB
Process Size   = 75 KB

Internal Fragmentation = 100 - 75
                       = 25 KB
```

```text
+----------------------+
| Process: 75 KB       |
+----------------------+
| Wasted: 25 KB        |
+----------------------+
| Total: 100 KB        |
+----------------------+
```

### 7.2 External Fragmentation

External fragmentation occurs when free memory is divided into small, non-contiguous blocks.

The total free memory may be sufficient, but a process cannot be allocated memory because no single contiguous block is large enough.

Example:

```text
Free Block 1 = 100 KB
Free Block 2 = 200 KB
Free Block 3 = 150 KB

Total Free Memory = 450 KB
```

A process requests 300 KB.

Although total free memory is 450 KB, allocation may fail because no single contiguous block has 300 KB.

### Internal vs External Fragmentation

| Internal Fragmentation | External Fragmentation |
|---|---|
| Wasted space inside allocated blocks | Wasted space between allocated blocks |
| Common in fixed-size allocation | Common in variable-size contiguous allocation |
| Allocated block is larger than required | Free memory is split into small holes |
| Paging can cause internal fragmentation | Segmentation can cause external fragmentation |

## 8. Compaction

Compaction is a technique used to reduce external fragmentation.

It moves processes in memory so that scattered free spaces are combined into one large continuous block.

### Before Compaction

```text
+------------------+
| P1               |
+------------------+
| Free: 100 KB     |
+------------------+
| P2               |
+------------------+
| Free: 200 KB     |
+------------------+
| P3               |
+------------------+
| Free: 150 KB     |
+------------------+
```

### After Compaction

```text
+------------------+
| P1               |
+------------------+
| P2               |
+------------------+
| P3               |
+------------------+
| Free: 450 KB     |
+------------------+
```

### Advantages

- Reduces external fragmentation.
- Combines scattered free memory.

### Disadvantages

- Requires moving processes.
- Can be expensive.
- Requires dynamic relocation support.

**Important:** Compaction reduces external fragmentation but does not eliminate internal fragmentation.

## 9. Swapping

Swapping is a memory management technique in which a process is temporarily moved from main memory to secondary storage and later brought back.

The process of moving a process out of RAM is called swap out.

The process of bringing it back is called swap in.

### Diagram

```text
         Main Memory
              |
              | Swap Out
              v
       Secondary Storage
              |
              | Swap In
              v
         Main Memory
```

### Advantages

- Allows more processes to be managed than can fit in RAM simultaneously.
- Helps improve memory utilization.

### Disadvantages

- Disk or SSD access is slower than RAM.
- Excessive swapping reduces performance.
- Requires time to move process memory.

## 10. Paging

Paging is a memory management technique in which logical memory is divided into fixed-size blocks called pages, and physical memory is divided into fixed-size blocks called frames.

A page can be placed into any available frame.

The page size and frame size are equal.

### Important Terms

**Page:** Fixed-size block of logical memory.

**Frame:** Fixed-size block of physical memory.

**Page Table:** A data structure that maps pages to frames.

### Diagram

Logical Memory:

```text
+-------------+
| Page 0      |
+-------------+
| Page 1      |
+-------------+
| Page 2      |
+-------------+
| Page 3      |
+-------------+
```

Physical Memory:

```text
+-------------+
| Frame 0     |
+-------------+
| Frame 1     |
+-------------+
| Frame 2     |
+-------------+
| Frame 3     |
+-------------+
| Frame 4     |
+-------------+
| Frame 5     |
+-------------+
```

Pages can be stored in different frames.

### Example

Suppose:

```text
Page 0 -> Frame 3
Page 1 -> Frame 1
Page 2 -> Frame 5
Page 3 -> Frame 2
```

The page table stores these mappings.

### Page Table

| Page Number | Frame Number |
|---|---|
| 0 | 3 |
| 1 | 1 |
| 2 | 5 |
| 3 | 2 |

### Advantages of Paging

- Eliminates external fragmentation in physical memory allocation.
- Allows non-contiguous memory allocation.
- Supports virtual memory.
- Simplifies memory allocation.

### Disadvantages of Paging

- Can cause internal fragmentation.
- Requires page tables.
- Address translation introduces overhead.
- Page tables consume memory.

---

## 11. Address Translation in Paging

In paging, a logical address is divided into two parts:

1. Page Number
2. Page Offset

```text
Logical Address
+----------------+----------------+
|  Page Number   |  Page Offset   |
+----------------+----------------+
```

The page number is used to find the corresponding frame number in the page table.

The offset identifies the exact location within that frame.

### Formula

```text
Physical Address = Frame Number * Page Size + Offset
```

### Solved Numerical 1: Find Page Number and Offset

Suppose:

```text
Logical Address = 2050 bytes
Page Size       = 1024 bytes
```

Find the page number and offset.

Formula:

```text
Page Number = Logical Address / Page Size

Offset = Logical Address % Page Size
```

Calculation:

```text
Page Number = 2050 / 1024
            = 2

Offset = 2050 % 1024
       = 2
```

Therefore:

```text
Page Number = 2
Offset      = 2
```

### Solved Numerical 2: Find Physical Address

Suppose the page table contains:

```text
Page 0 -> Frame 3
Page 1 -> Frame 1
Page 2 -> Frame 5
Page 3 -> Frame 2
```

Given:

```text
Logical Address = 2050
Page Size       = 1024 bytes
```

From the previous example:

```text
Page Number = 2
Offset      = 2
```

Page 2 maps to Frame 5.

Formula:

```text
Physical Address = Frame Number * Page Size + Offset

                 = 5 * 1024 + 2

                 = 5120 + 2

                 = 5122
```

Final Answer:

```text
Physical Address = 5122 bytes
```

## 12. Page Number and Offset Calculation Using Bits

Suppose:

```text
Logical Address Size = 16 bits
Page Size = 1024 bytes
```

Since:

```text
1024 = 2^10
```

The page offset requires 10 bits.

Total logical address bits = 16.

Therefore:

```text
Page Number Bits = 16 - 10
                 = 6 bits

Offset Bits = 10 bits
```

Logical address structure:

```text
+----------------------+----------------------+
| Page Number (6 bits) | Offset (10 bits)     |
+----------------------+----------------------+
```

Number of pages:

```text
2^6 = 64 pages
```

Page size:

```text
2^10 = 1024 bytes
```

**Important Formulas**

```text
Offset Bits = log2(Page Size)
```

```text
Page Number Bits = Logical Address Bits - Offset Bits
```

```text
Number of Pages = 2^(Page Number Bits)
```

```text
Number of Frames = Physical Memory Size / Frame Size
```

## 13. Page Table

A page table is a data structure maintained by the operating system to map logical pages to physical frames.

Each process generally has its own page table or address-space mapping structure.

### Example

| Page Number | Frame Number |
|---|---|
| 0 | 4 |
| 1 | 7 |
| 2 | 2 |
| 3 | 5 |

If the CPU generates an address belonging to Page 2, the page table maps it to Frame 2.

### Page Table Entry (PTE)

A page table entry may contain:

- Frame number
- Valid/invalid bit
- Protection bits
- Dirty bit
- Reference/accessed bit
- Other architecture-dependent information

### Valid/Invalid Bit

A valid bit indicates whether a page table entry represents a valid mapping in the process's address space.

An invalid access may result in a page fault or protection exception, depending on the reason.

### Dirty Bit

The dirty bit indicates whether a page has been modified.

If a modified page must be removed from memory, it may need to be written back to storage.

### Reference Bit

The reference bit indicates whether a page has been accessed.

It is useful in page replacement algorithms.

## 14. Translation Lookaside Buffer (TLB)

TLB is a small, fast associative cache used by the MMU to store recently used page table entries.

It reduces the time required for address translation.

### Why is TLB Required?

Without TLB:

1. CPU generates a logical address.
2. MMU accesses the page table in memory.
3. MMU accesses the actual data in memory.

This may require two memory accesses.

With TLB:

1. CPU generates a logical address.
2. MMU searches the TLB.
3. If the mapping is found, the frame number is obtained quickly.
4. The actual data is accessed.

### Diagram

```text
          CPU
           |
           v
     Logical Address
           |
           v
          MMU
           |
           v
          TLB
        /     \
       /       \
    Hit         Miss
     |            |
     v            v
 Frame Number   Page Table
     |            |
     |            v
     |         Update TLB
     |            |
     +------------+
           |
           v
      Physical Address
           |
           v
       Main Memory
```

### TLB Hit

A TLB hit occurs when the required page table entry is found in the TLB.

### TLB Miss

A TLB miss occurs when the required page table entry is not found in the TLB.

The system must then obtain the mapping from the page table.

**Important:** A TLB miss is not the same as a page fault.

A TLB miss means the translation is not cached. The page may still be present in RAM.

A page fault occurs when the required page is not currently available in physical memory or when an access violates the page's permitted mapping.

## 15. Effective Access Time (EAT)

Effective Access Time is the average memory access time considering TLB hits and misses.

Assume:
- TLB lookup time = t
- Main memory access time = m
- TLB hit ratio = h
- One memory access is required for the page table lookup on a TLB miss.

### Formula

```text
EAT = h * (t + m) + (1 - h) * (t + 2m)
```

### Solved Numerical

Given:

```text
TLB Lookup Time = 10 ns
Memory Access Time = 100 ns
TLB Hit Ratio = 80% = 0.8
```

Formula:

```text
EAT = h * (t + m) + (1 - h) * (t + 2m)
```

Substitute:

```text
EAT = 0.8 * (10 + 100)
    + 0.2 * (10 + 200)

    = 0.8 * 110 + 0.2 * 210

    = 88 + 42

    = 130 ns
```

Final Answer:

```text
Effective Access Time = 130 ns
```

**Note:** This formula assumes a single-level page table and a simple memory access model. Actual access time depends on architecture and caching.

## 16. Types of Page Tables

Large virtual address spaces can require large page tables.

Operating systems use different page table structures to manage them efficiently.

### 16.1 Hierarchical Paging

Hierarchical paging divides a page table into multiple levels.

Instead of maintaining one huge page table, the system uses smaller page tables organized hierarchically.

Example:

```text
Logical Address
       |
       v
+------------------+
| Outer Page Table |
+------------------+
       |
       v
+------------------+
| Inner Page Table |
+------------------+
       |
       v
+------------------+
| Frame Number     |
+------------------+
```

Advantages:
- Avoids allocating one large contiguous page table.
- Page table memory can be allocated as needed.

Disadvantages:
- Additional memory accesses may be required for address translation.
- More complex than a single-level page table.

### 16.2 Hashed Page Table

A hashed page table uses a hash function to locate page table entries.

It is useful for large address spaces, particularly in some 64-bit systems.

### 16.3 Inverted Page Table

An inverted page table contains one entry for each physical frame rather than one entry for each virtual page.

Each entry stores information about which process and virtual page occupy that frame.

Advantages:
- Can significantly reduce page table memory requirements.

Disadvantages:
- Address translation can be more complex.
- Searching or hashing may be required to find an entry.

### Comparison

| Page Table Type | Key Feature |
|---|---|
| Single-Level | One page table per address space |
| Hierarchical | Multiple levels of page tables |
| Hashed | Uses hashing to locate entries |
| Inverted | One entry per physical frame |

## 17. Segmentation

Segmentation is a memory management technique in which a program is divided into logical, variable-sized units called segments.

Examples of segments:

- Code Segment
- Data Segment
- Stack Segment
- Heap Segment

Unlike paging, segmentation uses variable-sized blocks.

### Diagram

```text
Program
   |
   +------ Code Segment
   |
   +------ Data Segment
   |
   +------ Stack Segment
   |
   +------ Heap Segment
```

### Logical Address in Segmentation

A logical address consists of:

1. Segment Number
2. Offset

```text
+------------------+------------------+
| Segment Number   | Offset           |
+------------------+------------------+
```

### Segment Table

Each segment table entry generally contains:

- Base: Starting physical address of the segment.
- Limit: Length of the segment.

### Address Translation

Formula:

```text
Physical Address = Base + Offset
```

Condition:

```text
Offset < Limit
```

If the offset is greater than or equal to the limit, the address is invalid.

### Solved Numerical

Suppose:

```text
Segment Number = 2
Base Address   = 4000
Limit          = 1200
Offset         = 100
```

Check:

```text
Offset < Limit

100 < 1200
```

The address is valid.

Physical address:

```text
Physical Address = Base + Offset

                 = 4000 + 100

                 = 4100
```

Final Answer:

```text
Physical Address = 4100
```

### Invalid Address Example

Suppose:

```text
Base Address = 4000
Limit = 1200
Offset = 1500
```

Since:

```text
1500 >= 1200
```

The address is invalid.

A protection fault is generated.

### Advantages of Segmentation

- Matches the logical structure of programs.
- Supports protection at segment level.
- Supports sharing of logical program components.
- Allows segments to grow independently.

### Disadvantages of Segmentation

- Causes external fragmentation.
- Requires segment tables.
- Allocation can be complex.

---

## 18. Paging vs Segmentation

This is a very important interview question.

| Paging | Segmentation |
|---|---|
| Divides memory into fixed-size pages | Divides program into variable-sized segments |
| Physical memory is divided into frames | Physical memory is allocated to variable-sized segments |
| Page size is fixed | Segment size varies |
| Uses page table | Uses segment table |
| Logical address = Page Number + Offset | Logical address = Segment Number + Offset |
| Can cause internal fragmentation | Can cause external fragmentation |
| Usually transparent to programmer | Represents logical program units |
| Simplifies physical memory allocation | Supports logical protection and sharing |

### Key Difference

Paging is mainly a physical memory management technique.

Segmentation is based on the logical structure of a program.

---

## 19. Segmentation with Paging

Some systems combine segmentation and paging.

In this technique:

1. A program is divided into logical segments.
2. Each segment is divided into fixed-size pages.
3. Pages are mapped to physical frames.

### Advantages

- Preserves logical program organization.
- Reduces external fragmentation associated with allocating whole variable-sized segments.
- Supports page-level memory allocation.

### Disadvantages

- More complex address translation.
- Requires both segment and page table structures.

---

## 20. Internal vs External Fragmentation in Paging and Segmentation

| Technique | Fragmentation |
|---|---|
| Fixed Partitioning | Internal |
| Variable Partitioning | External |
| Paging | Internal |
| Segmentation | External |
| Segmentation with Paging | Internal fragmentation may occur in the final page of a segment |

### Why Does Paging Cause Internal Fragmentation?

Pages and frames have fixed sizes.

If a process does not completely use its final page, the remaining space is wasted.

### Example

Page size:

```text
4 KB
```

Process memory required:

```text
10 KB
```

Number of pages required:

```text
Ceiling(10 / 4) = 3 pages
```

Total allocated memory:

```text
3 * 4 = 12 KB
```

Internal fragmentation:

```text
12 - 10 = 2 KB
```

Final Answer:

```text
Internal Fragmentation = 2 KB
```

## 21. Dynamic Loading and Dynamic Linking

### Dynamic Loading

Dynamic loading means a routine is loaded into memory only when it is called.

Advantages:
- Saves memory.
- Unused routines do not need to be loaded.

Example:

A program has multiple features, but a particular feature's code is loaded only when the user accesses it.

### Dynamic Linking

Dynamic linking means linking library routines to a program at execution time or when they are first needed, rather than fully linking all library code into the executable beforehand.

Advantages:
- Reduces executable size.
- Allows multiple programs to share library code.
- Makes library updates easier in supported environments.

### Difference

| Dynamic Loading | Dynamic Linking |
|---|---|
| Loads routines when needed | Links library routines at runtime |
| Focuses on loading code | Focuses on resolving library references |
| Saves memory by avoiding unused routines | Supports shared libraries and smaller executables |

## 22. Important Memory Management Formulas

### 1. Physical Address in Simple Relocation

```text
Physical Address = Logical Address + Base Register
```

### 2. Page Number

```text
Page Number = Logical Address / Page Size
```

Use integer division.

### 3. Offset

```text
Offset = Logical Address % Page Size
```

### 4. Physical Address in Paging

```text
Physical Address = Frame Number * Page Size + Offset
```

### 5. Offset Bits

```text
Offset Bits = log2(Page Size)
```

### 6. Number of Pages

```text
Number of Pages = Logical Address Space / Page Size
```

### 7. Number of Frames

```text
Number of Frames = Physical Memory Size / Frame Size
```

### 8. Internal Fragmentation

```text
Internal Fragmentation = Allocated Memory - Required Memory
```

### 9. Segmentation Address Translation

```text
Physical Address = Base + Offset
```

Valid only when:

```text
Offset < Limit
```

### 10. Effective Access Time

```text
EAT = h * (t + m) + (1 - h) * (t + 2m)
```

Where:
- h = TLB hit ratio
- t = TLB lookup time
- m = Memory access time

## 23. Important Interview Questions and Answers

### Q1. What is memory management?

Memory management is the operating system function responsible for allocating, tracking, protecting, and deallocating memory.

### Q2. What is the difference between logical and physical addresses?

A logical address is generated by the CPU, while a physical address refers to the actual location in RAM.

### Q3. What is MMU?

MMU stands for Memory Management Unit. It translates logical addresses into physical addresses and supports memory protection.

### Q4. What is address binding?

Address binding is the process of mapping program addresses to memory addresses.

### Q5. What are the three types of address binding?

1. Compile-Time Binding
2. Load-Time Binding
3. Execution-Time Binding

### Q6. What is contiguous memory allocation?

It is a memory allocation technique in which each process occupies one continuous block of physical memory.

### Q7. What are First Fit, Best Fit, and Worst Fit?

- First Fit selects the first sufficiently large block.
- Best Fit selects the smallest sufficiently large block.
- Worst Fit selects the largest available block.

### Q8. What is fragmentation?

Fragmentation is memory wastage caused by inefficient memory allocation and deallocation.

### Q9. What is the difference between internal and external fragmentation?

Internal fragmentation is wasted space inside allocated memory, while external fragmentation is scattered free memory between allocated blocks.

### Q10. What is compaction?

Compaction moves processes in memory to combine scattered free spaces into a larger contiguous block.

### Q11. What is swapping?

Swapping moves processes between main memory and secondary storage to manage memory availability.

### Q12. What is paging?

Paging divides logical memory into fixed-size pages and physical memory into equal-sized frames.

### Q13. What is a page table?

A page table maps virtual page numbers to physical frame numbers.

### Q14. What is a TLB?

TLB is a fast cache that stores recently used page table entries to speed up address translation.

### Q15. What is a TLB hit?

A TLB hit occurs when the required page table entry is found in the TLB.

### Q16. What is a TLB miss?

A TLB miss occurs when the required page table entry is not found in the TLB.

### Q17. Is a TLB miss the same as a page fault?

No. A TLB miss means the translation is not cached. A page fault means the requested page is not currently available in physical memory or the access is invalid.

### Q18. What is segmentation?

Segmentation divides a program into variable-sized logical units called segments.

### Q19. What is the difference between paging and segmentation?

Paging uses fixed-size pages, while segmentation uses variable-sized logical segments.

### Q20. Which causes internal fragmentation: paging or segmentation?

Paging can cause internal fragmentation because the final page may not be completely used.

### Q21. Which causes external fragmentation?

Variable-sized contiguous allocation and pure segmentation can cause external fragmentation.

### Q22. What is an inverted page table?

An inverted page table maintains one entry for each physical frame instead of one entry for every virtual page.

### Q23. What is hierarchical paging?

Hierarchical paging divides a large page table into multiple levels to reduce the need for one large contiguous page table.

### Q24. What is dynamic loading?

Dynamic loading loads a routine into memory only when it is required.

### Q25. What is dynamic linking?

Dynamic linking resolves library references at runtime or when needed instead of including all library code directly in the executable.

## 26. Unit 7 Summary

Memory Management is responsible for managing RAM efficiently and safely.

Important techniques include:

- Contiguous Memory Allocation
- Paging
- Segmentation
- Swapping
- Compaction
- Dynamic Loading
- Dynamic Linking

Important hardware and data structures include:

- MMU
- Page Table
- TLB
- Segment Table

**Remember for placements:**

- Paging divides memory into fixed-size pages and frames.
- Segmentation divides programs into variable-sized logical units.
- Paging can cause internal fragmentation.
- Segmentation can cause external fragmentation.
- TLB reduces address translation time.
- A TLB miss is not necessarily a page fault.
- The MMU translates logical addresses into physical addresses.
